## 第一部分：隐私政策

本部分阐述了我们在处理个人信息过程中的原则与实践。鉴于本服务的技术特性，我们需要明确界定数据处理活动中的角色与责任。

### 1. 角色定位与适用范围

#### 1.1 角色界定

本服务在个人信息处理活动中扮演受托处理者的角色：

- **个人信息处理者：** 指集成本服务的第三方开发者应用（如"永昼天气 Eternal"、"腕上信驿 WearPost"）。开发者负责向其最终用户（下称"用户"）收集个人信息，并承担《中华人民共和国个人信息保护法》规定的处理者责任。
- **受托处理者：** 指 MingChengAPI。我们仅依据开发者的指令（API 调用）代为处理数据，不独立决定处理目的与方式。
- **个人信息主体：** 指开发者应用的最终用户。

#### 1.2 适用范围

本隐私政策适用于本服务在处理以下业务场景数据时的所有行为：

- 天气数据查询接口；
- 邮件代理收发接口。

#### 1.3 沟通渠道

本服务不直接面向最终用户提供用户界面。最终用户关于个人信息的权利主张（查阅、复制、更正、删除等），应通过开发者应用的官方渠道提出，由开发者应用依法响应。如涉及需本服务配合的技术操作，开发者应用可联系我们进行协同处理。

### 2. 个人信息的收集与处理

我们仅在响应 API 调用请求时，为完成特定业务功能而处理必要信息。绝不超范围收集。

#### 2.1 天气服务

- **收集字段：** 地理位置信息（由设备 GNSS 或基站生成的经纬度坐标）、设备标识符（设备型号、唯一 ID）、系统版本、应用版本、请求源 IP。
- **处理目的：** 依据经纬度坐标向数据源查询对应位置的气象数据；依据设备信息进行服务激活验证、频次控制及异常流量分析。
- **处理逻辑：** 经纬度坐标仅用于当次请求的数据源查询，不进行持久化存储。设备信息经加密后存储于服务器端，用于生成统计报表。

#### 2.2 邮件服务

**收集字段：**

- **账户凭证：** 邮箱地址、IMAP/SMTP 服务器地址与端口、授权凭证（OAuth Token 或授权码）。
- **邮件元数据：** 收件人地址、邮件主题、收发时间戳、邮件大小、附件文件名。
- **邮件内容：** 邮件正文、附件数据流。
- **设备信息：** 设备型号、系统版本、网络制式。

**处理目的：** 代理开发者应用连接用户指定的邮件服务商（如 QQ 邮箱、163 邮箱、Gmail、Outlook 等），完成邮件的收取、发送、列表同步及已发送箱归档。

**处理逻辑：**

- **账户凭证：** 仅存储于内存中，用于建立与邮件服务商的连接。我们郑重承诺：不在数据库或文件系统中对用户的邮箱账户凭证进行持久化存储。当连接断开、开发者发起删除指令或内存释放时，相关凭证立即销毁。
- **邮件内容：** 仅作为数据转发的中继通道。邮件正文与附件在内存中进行流式处理，不进行持久化存储，不落盘，不记录全文日志。仅在内存中保留极短时间以确保网络传输的可靠性，传输完成后立即释放。
- **邮件元数据：** 用于构建 API 返回列表，部分字段（如收件人、主题）可能在传输链路日志中短暂出现，但我们会进行脱敏处理，且日志保留时间不超过 7 天。
- **设备信息：** 加密存储，用于服务统计与激活验证。

#### 2.3 运营与安全日志

我们自动收集访问日志，包括请求时间、请求接口、HTTP 状态码、耗时、User-Agent 等。

- 此类日志用于排查系统故障、防御网络攻击（如 DDoS、暴力破解）及性能优化。
- 日志中的敏感字段（如 Authorization 头、具体邮件内容）会被自动过滤或替换。

#### 2.4 我们不予主动收集的信息

- 最终用户的真实姓名、电话号码、身份证号码等身份识别信息（除非此类信息作为邮件内容的一部分由开发者主动传输，但我们不主动提取）。
- 用户在开发者应用内的操作行为轨迹（如按钮点击流），除非该操作触发了 API 调用。

### 3. 数据存储与安全保障

我们采取了符合行业标准的技术与管理措施，以保护个人信息安全。

#### 3.1 存储架构

- **存储地域：** 所有生产环境服务器均位于中华人民共和国大陆境内。
- **存储期限：**
  - 邮件相关数据：遵循"零持久化"原则，仅内存驻留，随连接生命周期结束而消失。
  - 设备与账户配置数据：加密存储，保留期限与开发者的应用生命周期一致，开发者删除应用或注销账号后立即匿名化或删除。
  - 运行日志：保留不超过 90 天，超期自动清理。
- **存储介质：** 采用具备冗余备份的分布式存储系统，防止单点故障导致的数据丢失。

#### 3.2 技术防护

- **传输加密：** 全站强制启用 HTTPS/TLS 1.3 加密传输，杜绝中间人攻击。
- **存储加密：** 敏感配置信息（如加密密钥、内部凭证）采用 AES-256 算法进行字段级加密存储。
- **访问控制：** 实行严格的 RBAC（基于角色的访问控制）权限管理体系。仅限必要的运维人员在授权范围内访问后台系统，且所有操作均有审计日志。
- **网络隔离：** 核心数据库部署于内网环境，不直接暴露公网访问端口。
- **日志脱敏：** 自动化日志系统会对敏感字段进行掩码处理（如将 1231231313 显示为 1231\*\*\*\*\*1313）。

#### 3.3 安全事件响应

尽管我们采取了严密的安全措施，但互联网环境不存在绝对的安全。如发生个人信息泄露等安全事件，我们将按照法律法规要求，及时通过邮件或应用内公告向开发者及受影响用户告知事件基本情况、影响范围及我们已采取的补救措施。

### 4. 信息共享、转让与披露

我们深知个人信息的重要性，不会随意共享、转让或披露您的信息，但以下情形除外：

#### 4.1 为实现功能所必需的共享

- **邮件服务：** 为完成邮件投递，我们必须将收件人地址、邮件主题与正文通过 SMTP 协议转发至目标邮件服务商的服务器。此为电子邮件协议的固有环节，无法避免。
- **天气服务：** 为查询天气数据，我们必须将经纬度坐标发送至上游天气数据源（如第三方气象服务商）。

#### 4.2 法律法规要求的披露

根据法律法规、司法裁决、政府主管部门（如网信办、公安机关）的强制性要求，我们需要提供相关信息的。

#### 4.3 保护权益所必需的披露

为维护国家安全、公共利益，或保护本服务、开发者、用户的生命财产安全及其他合法权益，在必要时披露的。

#### 4.4 委托处理

我们可能委托专业的云服务提供商（如 IDC 机房、CDN 加速服务商）提供基础设施支持。这些受托方仅能接触到提供服务所必需的最少数据，且受到严格的保密协议约束，我们无法控制其内部管理行为，但会选择信誉良好的合作伙伴。

#### 4.5 聚合信息

我们可能对设备信息进行去标识化处理，生成汇总的统计图表（如"昨日活跃设备型号分布"），此类信息无法识别特定个人，不属于个人信息范畴，不在本限制之内。

### 5. 您的权利

作为直接签约方，开发者拥有对其在本服务中注册账户的管理权：

- **访问与更正权：** 开发者可通过管理后台或 API 查询和更新其应用配置信息。
